# VantreLingo v0.1 — 产品需求

版本：1.0  
日期：2026-10-01  
状态：实施需求，不代表功能已完成。

## 0. 产品定位

VantreLingo 是 Windows 上的轻量语言小工具。

它不是输入法、聊天客户端、CRM、知识库或自动化 Agent。核心交互是：

> **选中内容 → 一个快捷动作 → 翻译、写回或整理 → 结束。**

第一版只有四项主功能：

| 编号 | 功能 | 必须交付 |
|---|---|---|
| F1 | LLM 多语言翻译 / 写回 | 阅读浮窗、审查/快速模式、多语言、智能语言记忆、可组合风格、安全原位写回 |
| F2 | 本地术语库 | 本地词条 CRUD、启停、导入导出、按语言/方向/上下文应用、冲突检测 |
| F3 | 客户信息与询盘整理 | 客户/产品需求提取、证据、缺项、歧义、冲突、建议追问 |
| F4 | 截图取字 | 主动框选、本地 OCR、结果编辑、进入翻译或客户整理 |

“第一版不接 API”指不连接 VANTRE 独立站、ERP、报价夹、CRM、邮箱或其他业务系统 API。  
翻译与客户整理所需的 LLM Provider 连接仍然保留。

## 1. 平台与基座

### 1.1 固定基座

使用 STranslate 固定快照做裁剪式派生：

- 仓库：`STranslate/STranslate`
- Tag：`v2.0.10`
- Commit：`2a75118fe0fabc1135a619f4393eb3a8d936c5cd`
- 技术基础：C# / .NET 10 / WPF
- 第一版正式支持：Windows 11 x64
- 上游许可证：MIT

不引入 ZyntaxAI 源码，不另建 Electron、Node、Python、Go 常驻进程。

STranslate 已具备全局热键、选区取词、截图 OCR、翻译操作隔离以及替换翻译能力，因此本项目重点是裁剪与重构，而不是再造第二套桌面输入系统。

### 1.2 “最小”的定义

“最小”不等于 shallow clone，也不等于只隐藏菜单。

必须同时做到：

1. **源码范围精简**：只保留本产品需要的模块。
2. **依赖精简**：删除被移除功能对应的包、注册、资源与打包内容。
3. **运行时精简**：无后台剪贴板监听、无默认鼠标划词监听、无插件扫描下载、无云同步、无空闲网络轮询。
4. **UI 精简**：托盘 + 一个复用工具浮窗 + 设置窗口。
5. **数据精简**：小型本地 JSON；客户正文默认不落盘。

## 2. 统一入口

| 操作 | 默认入口 | 行为 |
|---|---|---|
| 阅读翻译 | `Alt+D` | 读取当前选区 → 只读浮窗；永远不修改来源 |
| 写作翻译 | `Ctrl+Alt+G` | 按当前“审查/快速”模式处理选区 |
| 截图取字 | `Alt+S` | 主动框选 → 本地 OCR → 编辑识别结果 → 后续动作 |
| 客户整理 | 浮窗按钮/托盘 | 处理明确选中的文本、OCR 文本或用户手动粘贴内容 |
| 输入翻译 | 托盘入口 | 在同一浮窗输入，不创建聊天窗口 |

快捷键必须可修改并检测冲突。

禁止默认注册 `Ctrl+C`、`Ctrl+V`、`Ctrl+A` 等基础系统编辑快捷键。

默认不常驻读取剪贴板，不在无选区时偷偷翻译旧剪贴板内容。

## 3. 翻译语言策略

### 3.1 默认模式

默认语言模式：

> **自动识别源语言；外语 → 中文；中文 → 最近有效外语；首次没有记忆时中文 → 英文。**

例：

```
首次：
中文 → 英文

随后读取日文：
日文 → 中文
之后再写中文：
中文 → 日文

随后读取德文：
德文 → 中文
之后再写中文：
中文 → 德文
```

### 3.2 最近有效外语

只保存“最近有效外语”，不机械保存“上一次目标语言”。

应更新记忆：

- 成功识别的外语 → 中文；
- 用户明确手动选择中文 → 某外语且成功完成；
- 有效翻译操作完成且仍是当前请求。

不得更新：

- 翻译失败；
- 用户取消；
- 已被更新请求替代的旧请求；
- 无法可靠识别语言；
- 只有数字、型号、URL、代码片段等；
- 客户整理操作；
- OCR 仅识别但未执行有效翻译。

用户可：

- 手动选择源语言；
- 手动选择目标语言；
- 固定目标语言；
- 恢复智能模式；
- 清除最近外语记忆。

### 3.3 多语言

语言选择必须支持搜索。

产品不能把“多语言”限制成中英两种；UI 默认简化显示智能/中文/英语/最近使用语言，其他语言从搜索选择器进入。

## 4. 阅读模式

`Alt+D` 永远是只读。

流程：

1. 捕获明确选区；
2. 语言路由；
3. 本地术语匹配；
4. LLM 翻译；
5. 浮窗展示。

浮窗至少显示：

- 原文；
- 译文；
- 实际源语言；
- 实际目标语言；
- 当前风格（如有）；
- 复制；
- 切换语言；
- 重新翻译；
- 进入客户整理。

阅读模式不得提供默认原位覆盖动作，避免阅读时误改内容。

## 5. 写作模式

`Ctrl+Alt+G` 使用当前写作模式。

首次使用默认：**审查模式**。

用户明确切换为快速模式后，本地记住。

### 5.1 审查模式

显示：

- 原文；
- 完整译文；
- Diff；
- 风格；
- 语言；
- 保护项/风险提示；
- 可编辑译文。

动作：

- 替换原选区；
- 追加到原选区后；
- 复制；
- 重试；
- 取消。

Diff 只是文本差异辅助，不得显示为“模型已证明翻译正确”。

### 5.2 快速模式

目标：用户写完中文，按快捷键即可变成目标外语，不弹主窗口。

成功条件全部满足后：

1. 得到完整非流式最终译文；
2. 保护项校验通过；
3. 当前请求仍有效；
4. 原应用、窗口、控件、选区仍与捕获快照一致；
5. 风格配置允许快速模式；

才允许一次性覆盖原选区。

快速模式：

- 不弹主窗口；
- 不抢焦点；
- 不先删除原文；
- 不写入流式半成品；
- 不模拟 Enter；
- 不自动发送消息；
- 不使用 `Ctrl+A` 兜底。

失败时：

- 原文保持不变；
- 使用不抢焦点的状态提示；
- 结果可暂存到内存供用户主动查看；
- 不因为失败突然切换成会修改焦点的审查窗口。

### 5.3 安全写回

捕获时生成 SelectionSnapshot，至少保存：

- process id；
- top-level window；
- 控件标识；
- 可用时的 selection range / UI Automation 信息；
- 原文；
- 原文 hash；
- 捕获时间；
- 请求 id。

应用译文前重新验证。

无法可靠验证选区范围的应用：

> 只允许阅读、审查和复制，不宣称支持安全快速覆盖。

剪贴板兼容写回时需要保护剪贴板序号：如果等待 LLM 期间用户已复制新内容，不得在完成后恢复旧剪贴板覆盖用户新数据。

## 6. LLM Provider

第一版只实现一个统一 OpenAI-compatible Adapter，但允许保存多个 Provider 配置。

每次操作默认只调用一个选中的模型，不做多模型投票。

配置：

- display name；
- base URL；
- model；
- API key；
- timeout；
- temperature（若兼容）；
- max output；
- 自定义 headers（非必需时不开放）。

API key 使用 Windows DPAPI CurrentUser 加密保存。

禁止：

- 把密钥写日志；
- 把真实客户原文写诊断日志；
- 自动把内容发给备用 Provider；
- Provider 失败后无提示地切到另一家。

## 7. 翻译风格系统

风格不是一个自由文本框，而是 typed preset：

> **场景 + 专业方向 + 语气 + 性格/表达方式 + 篇幅 + 忠实度**

### 7.1 维度

**场景**

- 通用
- 客户邮件
- 即时聊天
- 技术说明
- 产品说明
- GitHub / 开发
- 正式文件

**专业方向**

- 通用
- OEM/ODM 制造
- 竹木制品 / 梳刷
- 外贸采购
- 包装
- 3D / CAD / 制造技术
- 软件开发
- 用户自定义

**语气**

- 中性
- 专业商务
- 友好礼貌
- 严肃严谨
- 幽默风趣

**性格 / 表达**

- 自然
- 直接务实
- 温和
- 活泼
- 刻板直译

**篇幅**

- 保持
- 精简
- 展开说明

**忠实度**

- 标准
- 高忠实
- 严格忠实

### 7.2 组合与冲突

组合必须先经过本地冲突规则，不把明显冲突交给 LLM 自己决定。

第一版至少定义：

- 正式文件 × 幽默风趣：禁止；
- 正式文件 × 活泼：禁止；
- 严格忠实 × 大幅精简：禁止；
- 幽默风趣 × 刻板直译：禁止；
- 正式文件自动锁定高/严格忠实与内容保护。

用户可保存自定义 preset。

### 7.3 自定义提示词

允许在 typed preset 后增加自由文本要求。

但：

- 新建/修改后的自由提示词默认只能用于审查模式；
- 用户明确测试并授权后，才能允许其进入快速模式；
- 提示词再次修改后，快速授权失效。

## 8. 正式文件保护

“正式文件”不是简单的“更正式措辞”。

必须额外保护：

- 金额；
- 数量；
- 百分比；
- 尺寸；
- 单位；
- 日期；
- 型号；
- SKU；
- URL；
- 邮件；
- 代码和模板占位符；
- 否定；
- 条件；
- 责任主体；
- 已有承诺强度。

LLM 不得自行添加：

- 未提供的 MOQ；
- 价格；
- 认证；
- 交期承诺；
- 退款承诺；
- 质量保证；
- 运输承诺；
- 工艺能力。

发现受保护信息丢失或明显改变时：

- 审查模式：标风险；
- 快速模式：阻止写回。

## 9. 本地术语库

### 9.1 存储

UTF-8 JSON，版本化 schema。

字段建议：

```json
{
  "id": "term-001",
  "status": "draft",
  "source_language": "zh-CN",
  "target_language": "en",
  "source": "气垫梳",
  "target": "cushion brush",
  "contexts": ["product", "oem"],
  "direction": "forward",
  "forbidden_variants": [],
  "notes": ""
}
```

### 9.2 规则

- 本地 CRUD；
- 启停；
- 导入/导出；
- draft/active；
- 按源/目标语言匹配；
- 按上下文匹配；
- 最长短语优先；
- 正确处理词边界；
- 同条件冲突词条不能同时 active；
- 支持禁止旧词和允许变体。

种子词库默认 draft，需要人工确认后激活。

不把本地词库自动同步到云端。

## 10. 客户信息与询盘整理

### 10.1 输入

只处理用户明确提供的：

- 选中文字；
- 手动粘贴；
- OCR 文本。

第一版不自动读取 Gmail、WhatsApp、CRM、浏览器整页或客户数据库。

### 10.2 输出结构

固定四区：

1. **客户信息**
2. **分产品需求**
3. **缺项 / 歧义 / 冲突**
4. **建议追问**

每个字段包含状态：

- `known`
- `missing`
- `ambiguous`
- `conflicting`
- `not_applicable`

已知字段尽可能附 evidence，引用输入中的对应片段。

### 10.3 客户字段

尽可能抽取：

- 姓名；
- 公司；
- 国家/地区；
- 邮箱；
- 电话；
- 渠道；
- 角色；
- 目的地；
- 目标时间。

没有就保持 missing，不推断。

### 10.4 产品需求

每个产品分开，不允许多产品串值。

字段包括：

- 产品类型；
- 参考 SKU / 图片 / 型号；
- 数量；
- 主体材质；
- 尺寸；
- 齿/针/毛；
- 气垫；
- Logo；
- Logo 工艺；
- 表面工艺；
- 包装；
- 定制要求；
- 目标出货/到货时间；
- 目的地；
- 备注。

### 10.5 缺项逻辑

LLM 负责理解候选信息，本地规则负责缺项判定。

不能简单把所有空字段都追问。

例如：

- 客户明确“不要 Logo” → Logo artwork 不再 missing，而是 not_applicable；
- 客户不要包装 → 不追问包装印刷；
- 客户要求含运费报价 → 目的地成为关键缺项；
- 只要求产品报价、不要求运费 → 目的地可以是可选补充；
- “Christmas 前”保留原始时间表达，并标记需要确认具体日期，不擅自猜年份；
- 不把“希望收到货”自动解释为“工厂出货日期”。

### 10.6 事实边界

不得：

- 推断客户公司规模；
- 推断采购预算；
- 自动访问客户提供 URL；
- 声称已读取未上传附件；
- 补写未提供参数；
- 自动报价；
- 自动发送追问；
- 自动创建 CRM/RFQ/业务单。

## 11. OCR

默认快捷键：`Alt+S`。

流程：

1. 框选截图；
2. 本地 OCR；
3. 显示识别文本；
4. 用户可修正；
5. 选择“翻译”或“客户整理”。

第一版优先使用 `Windows.Media.Ocr`。

要求：

- 检查系统已安装的 OCR 语言；
- 不支持时明确提示；
- 不自动上传截图到云端；
- 不自动下载大型 OCR 模型；
- OCR 语言范围与 LLM 翻译语言范围必须分开说明。

## 12. 本地数据与隐私

默认落盘：

- 用户设置；
- Provider 元数据；
- DPAPI 加密 API key；
- 最近有效外语；
- 风格 preset；
- 本地术语；
- 快速模式授权状态。

默认不落盘：

- 客户正文；
- 每次翻译原文；
- 每次译文；
- OCR 截图；
- OCR 原文；
- 客户整理结果。

用户明确“另存”时才保存客户整理结果。

默认关闭：

- 遥测；
- 正文日志；
- 云同步；
- 自动更新；
- 后台业务任务。

## 13. 第一版不做

- 图片压缩、转 WebP、去背景、修图；
- 整份 PDF 翻译/拆并；
- 图片原位覆盖翻译；
- 报价、CBM、装箱、汇率计算；
- SEO 检查；
- 文件批量重命名；
- TTS/语音；
- 生词本；
- 聊天会话；
- RAG/知识库；
- 插件市场；
- 云备份；
- 自动发送消息；
- 自动创建业务单；
- 独立站/ERP/CRM API；
- 后台 Agent。

## 14. 完成定义

v0.1 不能只做到“界面看起来有”。

必须完成：

- Windows 11 x64 真实运行；
- 热键冲突处理；
- 选区读取与可验证安全写回；
- 请求取消与迟到结果隔离；
- 智能语言记忆；
- 多语言切换；
- 风格冲突规则；
- 正式文件保护；
- 本地术语库；
- 客户提取和本地缺项规则；
- 本地 OCR；
- API key 安全存储；
- 公开仓库无真实客户数据和密钥；
- 删除功能不再后台启动。
