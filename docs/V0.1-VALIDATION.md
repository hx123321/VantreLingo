## 已接通的实现

- M0：独立 WPF 宿主、单实例、托盘、一个复用工具窗口和设置窗口，无被裁剪功能的包/注册/后台任务。
- M1：一个 OpenAI-compatible 适配器及多配置管理，智能/固定/手动语言、最近有效外语、取消/迟到隔离，审查、Diff、受限原生写回与快速门控。
- M2：六维风格、本地冲突图、正式文件严格模式、有限保护项校验、已测试自定义提示的显式快速授权及配置指纹失效；JSON 术语 CRUD/启停/导入导出、最长匹配、语言/方向/上下文/词边界、冲突和变体。
- M3：客户与多产品四区整理、原文/范围/字段值证据验证、条件缺项、明确不适用、模糊时间、人工修订/导出/另存；主动框选、本地 OCR、语言检查和 MSIX 打包入口。
- 隐私：DPAPI CurrentUser、普通设置导出排除密钥、默认无正文/截图历史、日志、遥测、自动更新或业务系统调用。客户另存只通过显式文件选择。

## 不能据此认定全量通过的边界

原生 `Edit` 的范围与上下文验证不提供跨进程原子 compare-and-swap；最后一次验证与写入之间仍存在需实测的竞争边界。只尝试该控件，不盲写浏览器、VS Code、Word 或 RichEdit；这些应用读取成功时只审查/复制。发送后状态不确定不重试、不自动恢复，不提交语言记忆。详见 `M1-VALIDATION.md`。

证据校验只能证明片段及直接字段值来自输入，不能证明模型理解没有误差；多产品无法独立定位时降为歧义，用户可人工修订，导出明确标注人工修改。正式保护也仅覆盖已定义规则，不能保证任意提示绝无矛盾或模型绝无幻觉。

Windows 11 的浏览器/原生文本框/VS Code/Word 支持等级保持待测，不能用理论 API 支持或 Windows Server CI 替代。OCR 需要用户提供受信任签名身份和系统语言能力；仓库不包含证书或真实密钥。打包步骤见 `PACKAGING.md`。
